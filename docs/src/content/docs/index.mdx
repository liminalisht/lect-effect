**lect-effect** is a **TypeScript** backend that exposes a **[GraphQL](https://graphql.org/)** API whose types and validation are derived from **[Effect Schema](https://effect.website/docs/schema/introduction/)**, and whose resolvers run as **[Effect](https://effect.website/docs/getting-started/introduction/)** computations.

In one sentence:

> Write your *domain* as `Schema`s and `Effect`s, weave them into GraphQL with **[GQLoom](https://gqloom.dev/)**, and run them on a fully typed service environment provided via **[Effect Layers](https://effect.website/docs/requirements-management/layers/)**.

## What lect-effect uses (and why)

- **[GraphQL](https://graphql.org/)** as the external interface ([GraphQL Yoga](https://the-guild.dev/graphql/yoga-server/docs) server).
- **[GQLoom](https://gqloom.dev/)** (`@gqloom/core` + `@gqloom/effect`) to *weave* a schema from runtime types.
- **[Effect](https://effect.website/docs/getting-started/introduction/)** for:
  - `Effect<A, E, R>` programs (effects),
  - `Schema` as the single source of truth for runtime validation + types,
  - `Context.Tag` + `Layer` to model and provide services.
- **[PostgreSQL](https://www.postgresql.org/)** via [`@effect/sql`](https://github.com/Effect-TS/sql) and [`@effect/sql-pg`](https://github.com/Effect-TS/sql/tree/main/packages/pg).
- **Property-based tests** ([`fast-check`](https://fast-check.dev/)) + **Vitest** integration ([`@effect/vitest`](https://github.com/Effect-TS/vitest)).
- **Docs generation** via [`@effect/docgen`](https://github.com/Effect-TS/docgen), rendered in a [Starlight](https://starlight.astro.build/)/[Astro](https://astro.build/) docs site.
