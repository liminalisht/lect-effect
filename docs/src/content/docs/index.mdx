<Card title="Core Principles">

> Make the domain canonical, and re-index everything else against it.

- **Domain schemas are the center.** Schema definitions drive validation, decoding/encoding, arbitrary generation for tests, and shape every boundary.
- **Functions as morphisms.** Handlers take schema-defined inputs and return schema-defined outputs, typed with inputs, success, errors, and required services (DI-friendly, property-testable).
- **Effect everywhere.** Handlers and orchestration are Effect programs—cancellable, inspectable, schedulable—on both backend and frontend.
- **Derive interfaces, don’t handcraft.** GraphQL schema and resolvers wrap handlers; frontend GraphQL types and shared validators reuse the same schemas.
- **Explicit dependencies.** Packages enforce direction: domain is foundational; handlers/services depend on domain; backend and frontend consume but don’t leak back; the CLI codifies pipelines so generation and builds reflect those edges.
</Card>

<Card title="How the pieces fit">

- **Domain-first:** Define schemas in `@lect-effect/domain`; property tests come from arbitraries; validation/decoding is consistent across all consumers.
- **Handlers compose services:** `@lect-effect/handlers` binds schema inputs to Effectful business logic, declaring service dependencies (`R`), success (`A`), and errors (`E`).
- **Services provide capabilities:** `@lect-effect/services` exposes live layers (DB, config, logging) and interfaces the handlers expect.
- **GraphQL is derived, not hand-rolled:** `@lect-effect/graphql-schema` weaves schemas/handlers into GraphQL types and resolvers; backend consumes this directly, frontend generates typed queries from it.
- **Apps consume, never back-depend:** Backend and frontend import domain/handlers/services/graphql-schema; they do not contribute types back upstream, keeping edges clear.
- **Pipelines enforce edges:** The CLI codifies builds/codegen/docgen so dependency direction stays honest and coordinated releases stay in lockstep.

</Card>

<Card title="Usage snapshots">

- **Add a domain type:** create a `Schema` in `@lect-effect/domain`; arbitraries and validators come along for tests and UIs.
- **Implement a handler:** write an Effect that accepts the input schema, returns the output schema, and lists required services. It’s immediately usable by GraphQL, backend, and tests.
- **Expose via GraphQL:** weave handler + schemas in `@lect-effect/graphql-schema`; Yoga server picks it up; frontend codegen updates its typed operations.
- **Call from frontend:** use generated GraphQL types plus shared domain validators to keep forms and network boundaries in sync.
- **Document automatically:** run `./lect-effect.sh docs` to regenerate typed API docs for every package.
</Card>
